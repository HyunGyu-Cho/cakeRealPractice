# cart 스펙

> 확정일: 2026-07-25. 범위: 회원 일반 판매 상품 장바구니의 DB 전환과 선택 상품 주문 인계.
> 제외: 주문제작(`CUSTOM`) 옵션·이미지, 픽업 일시, 주문 생성·결제·재고 차감.

## 1. 개요와 유스케이스

- 이 도메인이 해결하는 문제 한 줄: 로그인 회원이 일반 판매 상품을 서버 장바구니에 보관하고, 최신 판매 정보로 검증한 선택 항목을 주문 단계에 인계한다.
- 주요 유스케이스:
  1. 회원 → 상품 상세에서 수량을 정해 담기 → 동일 상품이면 기존 수량에 합산
  2. 회원 → 장바구니 조회 → 최신 상품명·이미지·가격·재고와 판매 가능 상태 확인
  3. 회원 → 수량 변경 또는 단건·선택·전체 삭제 → PRG로 결과 확인
  4. 회원 → 판매 가능한 항목 선택 → 최신 가격·재고 재검증 후 픽업 설정 화면으로 이동

## 2. 상태값

- 장바구니 전용 status 컬럼은 만들지 않는다.
- 판매 중지·품절은 `products.status`와 `stock_quantity`로부터 계산하는 표시 상태이며 장바구니에 복제하지 않는다.
- 선택 여부는 요청 단위 값이고 픽업 일시는 주문 단계 값이므로 DB에 저장하지 않는다.

## 3. DB (V7_cart.sql + V0/V1 소급)

- `carts`: 회원당 최대 1행. 첫 상품 추가 시 지연 생성하고 비워져도 행은 유지한다.
- `cart_items`: 장바구니·상품·수량만 저장한다. 담은 가격은 저장하지 않는다.
- 제약: `carts.member_id` UNIQUE, `(cart_id, product_id)` UNIQUE, `quantity > 0` CHECK, 회원·장바구니·상품 FK.
- 이번 범위에서 `cart_item_options`, `cart_item_images`, 요구사항·픽업 컬럼을 생성하지 않는다.

## 4. 도메인 간 인터페이스

- 내가 제공할 공개 Service 메서드:
  - `CartService.getCheckoutItems(memberId, cartItemIds)` → `cartItemId`, `productId`, `quantity`, `currentUnitPrice`
  - `CartService.getTotalQuantity(memberId)` → 헤더 배지용 전체 수량 합계
- 내가 사용할 다른 도메인의 공개 Service 메서드:
  - `ProductService.getSalesInfo(productId)` → 최신 판매 가능 여부·가격·재고
  - `ProductService.getProductDetail(productId)` → 상품명·대표 이미지·유형 등 화면 출력 정보
- Cart Mapper는 `carts`, `cart_items`만 조회하며 상품 테이블을 JOIN하지 않는다.

## 5. 화면과 접근 권한

- `GET /cart`: 로그인 필수. 비로그인 접근은 로그인 성공 후 `/cart`로 복귀한다.
- 변경 요청: `POST /cart/items`, 수량 변경, 단건·선택·전체 삭제, 선택 주문 인계. 모두 로그인 필수이고 PRG를 사용한다.
- 상품 상세: `GENERAL`, `SAME_DAY`, `SEASON`만 실제 장바구니 폼을 노출한다. 비회원은 로그인 동선을 제공하고 `CUSTOM`은 주문제작 단계로 보낸다.
- 선택 주문: 검증 후 장바구니 항목 ID들을 `/orders/pickup`에 전달한다. 주문 생성과 장바구니 제거는 다음 도메인이 담당한다.
- 공통 헤더는 로그인 회원의 장바구니 전체 수량 합계를 서버 렌더링한다.

## 6. 비즈니스 규칙

- 수량은 최소 1, 최대 현재 재고다. 별도 10개 제한은 없고 초과 요청은 오류로 거절한다.
- 동일 회원·동일 상품은 한 항목으로 합산한다.
- 일반 판매 상품(`GENERAL`, `SAME_DAY`, `SEASON`)만 담을 수 있고 `CUSTOM`은 거절한다.
- 판매 중지·품절 항목은 자동 삭제하지 않고 비활성으로 표시하며 선택·주문을 차단한다.
- 조회·수량 변경·주문 인계마다 `getSalesInfo()`로 최신 가격·판매 여부·재고를 확인한다.
- 추가·수정은 회원 장바구니 행을 잠근 뒤 수행해 동시 요청의 중복 항목과 재고 초과를 막는다.
- 다른 회원 항목 접근은 존재하지 않는 항목과 동일한 404로 처리한다.
